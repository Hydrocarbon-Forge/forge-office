## Item 1 — Voice: Raw Mic Capture, Correct Sample Rate, Audible Self-Monitor

### Root Cause Verification (C6-diagnosed 1a–1d vs Reality)
1. **1a. Sample-rate mismatch (Verified)**:
   - *Original state:* `SAMPLE_RATE = 48000` was hardcoded, creating pitch/time warble and buffer drift whenever `audioCtx.sampleRate` was non-48k or when peers ran at differing context rates.
   - *Fix:* Captured `this.sr = audioCtx.sampleRate` dynamically in `init()`, `enableMic()`, and pipeline setup. Derived 20ms chunk size dynamically: `CHUNK = Math.round(this.sr * 0.02)`. Eliminated all hardcoded `48000` literals. Packet carries `sr: this.sr`, and receivers dynamically resample cross-sample-rate packets if necessary so timing stays precisely 20ms at the receiver context rate.
   - *Measured device rate:* On the test machine, `audioCtx.sampleRate` was measured to be **48000 Hz**, yielding `chunkSize = 960` samples.

2. **1b. Re-chunking jitter & ScriptProcessor constraint (Crucial Diagnosis Nuance)**:
   - *C6 Diagnosis:* C6 suggested setting `createScriptProcessor(CHUNK, 1, 1)` to eliminate the accumulator.
   - *Actual Web Audio Specification:* Calling `ctx.createScriptProcessor(960, 1, 1)` or `882` throws an immediate `IndexSizeError: buffer size (960) must be 0 or a power of two between 256 and 16384`. Web Audio strictly enforces powers of 2 (256, 512, 1024, 2048, etc.).
   - *Actual root cause of chop:* The 18ms throttle `if (now - this.lastTxTime < 18) return;` was silently dropping consecutive chunks generated in the same callback when 1024 samples flushed into the 960 accumulator!
   - *Fix:* Configured `bufferSize = 512` (power of 2, low latency ~10.6ms), removed the 18ms throttle entirely, and flushed exact `CHUNK` slices continuously (`while (accumulator.length >= CHUNK)`). Zero lost audio frames, zero boundary misalignment.

3. **1c. Gate + AGC Removal (Verified)**:
   - *Original state:* RMS threshold `> 0.06` over 3 chunks with 350ms hangover, peak normalization with up to ×3.5 gain, and browser audio processing enabled. Normal/quiet speech was clipped or dropped, and room noise was amplified.
   - *Fix:* Completely removed `gateOpen`, `consecutiveVoiceChunks`, `gateCloseTimer`, and AGC normalization scaling. `getUserMedia` constraints set strictly to `{ echoCancellation: false, noiseSuppression: false, autoGainControl: false }`. Samples are clamped solely to $[-1.0, 1.0]$ and converted directly to PCM16. `level` is calculated as the raw peak for the HUD meter only and is never used for gating. Chunks transmit unconditionally while mic is unmuted.

4. **1d. Local Self-Monitor (Verified & Implemented)**:
   - *Implementation:* Created a local self-monitor pipeline: `micSource -> selfMonitorGainNode (0.35 default) -> audioCtx.destination`.
   - *Default state:* ON (`isSelfMonitorEnabled = true`).
   - *HUD Toggle:* Added `🎧 MONITOR: ON / OFF` button on HUD (`#monitorBtn`) and start screen checkbox (`#startMonitorCheckbox`). Updated HUD pill instructions.
   - *Toast:* One-time guidance toast displays upon enabling mic: `"Heard yourself? Lower the music (M) if there's feedback."`.
