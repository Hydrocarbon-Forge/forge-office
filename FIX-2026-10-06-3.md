## Item 1 — Voice: raw mic capture, correct sample rate, audible self-monitor

The current `web/voice.js` pipeline is scratchy and the user often cannot hear their own voice at all.
C6-diagnosed root causes (verify each; note in report if different):

### 1a. Sample-rate mismatch (scratchy/warped audio)
`SAMPLE_RATE = 48000` is hardcoded, but the shared `AudioContext` runs at the DEVICE rate
(`audioCtx.sampleRate`, commonly 44100). Capture (ScriptProcessor `onaudioprocess`) delivers samples at
the context rate, but playback does `ctx.createBuffer(1, chunk.length, SAMPLE_RATE)` declaring them as
48k → ~8% pitch/time warble and chunk-timing drift.
Fix: single source of truth — capture `this.sr = audioCtx.sampleRate` in `init()`. Derive the chunk size
from it (`CHUNK = Math.round(this.sr * 0.02)` = 20ms). Use `this.sr` in every `createBuffer`. Remove the
hardcoded 48000 constant. (The server relay and base64 payload are rate-agnostic — they just carry
samples — but include the rate in the voice packet (`sr` field) so receivers can log/assert it matches;
if a receiver's ctx rate differs from the sender's, the receiver must resample or, simpler, create the
buffer at its OWN ctx rate with the correct sample count so timing stays 20ms per chunk — pick the
approach that keeps 20ms/chunk at any rate and document it.)

### 1b. Re-chunking jitter
`createScriptProcessor(1024, 1, 1)` + a 960-sample accumulator misaligns chunk boundaries (1024≠960),
so chunks arrive with irregular boundaries → audible chop. Fix: set the ScriptProcessor buffer size to
exactly `CHUNK` (20ms at `this.sr` — valid, it's within the 256–16384 range), so each
`onaudioprocess` event IS one chunk. Drop the accumulator. Remove the 18ms throttle too.

### 1c. Gate + AGC = "cannot hear me"
`processAndSendChunk` only transmits when RMS > 0.06 for 3 consecutive chunks (with a 350ms hangover)
and then normalizes peak to 0.8 with up to ×3.5 gain. Quiet/normal speech gets dropped entirely, and the
AGC amplifies room noise. Per user instruction: **RAW MIC, NO PROCESSING** on the input.
Fix:
- Remove the RMS gate, the `gateOpen`/`consecutiveVoiceChunks`/`gateCloseTimer` logic, and the AGC
  scaling entirely.
- Send EVERY chunk unconditionally (while mic enabled and not muted). Convert float→PCM16 with only a
  clamp to ±1.0 (no gain, no normalization, no threshold).
- `getUserMedia` constraints → raw: `echoCancellation: false, noiseSuppression: false, autoGainControl:
  false`. (No minimum-level logic anywhere.)
- `level` in the packet = raw peak of the chunk (for the HUD indicator only — never used for gating).

### 1d. You can never hear yourself (no echo)
The server relay intentionally does not echo voice back to the sender, so the user can NEVER know if
their mic is working. Fix: add a LOCAL SELF-MONITOR on the sender's own client: raw mic → `GainNode`
(~0.35) → `ctx.destination`, so you hear your own voice in your own speakers/headphones.
- Default: ON (the user explicitly wants to hear themselves).
- Add a HUD toggle for it (a small "monitor" button next to the voice indicator, and/or a key — pick one,
  keep it consistent with the other HUD toggles, and document it in the report + start screen).
- On enable, show a one-time toast: "Heard yourself? Lower the music (M) if there's feedback." (Feedback
  risk is real with speakers; with headphones it's fine. Do NOT add echo cancellation back — keep it raw.)
- The monitor gain must be independent of the distance/occlusion math (it's local playback only).

  or pollen motes, a signpost. Pick a tasteful set (~8–15 distinct things), vary scale/rotation/position
  with a SEEDED RNG so it's stable across reloads but never grid-aligned.

  must not read as a different, cheaper layer.
