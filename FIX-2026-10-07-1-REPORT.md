## Item-by-Item Breakdown & Root Cause Confirmation

### Item 1: Meeting-Room Dock/Undock Bug + Real Chrome Screen Share
- **Diagnosed Root Cause:**
  1. `handleInteraction()` opened the projector settings modal instead of undocking when `projectorDocked` was true.
  2. Walk-away auto-undock cleared local state incompletely without broadcasting or halting local media streams.
  3. Presentation canvas showed a fake stylized panel rather than a real screen share.
- **Confirmation:** Confirmed. Pressing `E` was trapped in the settings modal branch; walking away left the local player flagged as docked; screen share was purely a synthetic canvas mock.
- **Fix Applied:**
  - Modified `handleInteraction()` in `web/game.js`: pressing `E` while near the projector directly calls `undockProjector()` if docked, or `dockProjector()` if not docked.
  - Projector settings modal moved to a dedicated `#projectorSettingsBtn` button and canvas click.
  - Implemented `startScreenShare()` in `web/game.js` using `navigator.mediaDevices.getDisplayMedia({ video: { frameRate: 15 } })`. Attached track `ended` listener to auto-undock when user stops sharing via browser chrome.
  - Added hidden `<video id="projectorVideo">` in `web/index.html` to feed decoded frames to `web/render.js`'s projector canvas.
  - Updated `server.js` projector dock handler to support `screenShareActive` flag and `topic` field in broadcasts.
  - Enforced single-occupant docking with `projector-busy` message for competing clients.
- **Verification:**
  - Automated WS test (`test/round6-interaction-tests.js` Tests 4 & 8) passed: single-occupant enforcement, `projector-busy` rejection, `screenShareActive` flag relay, and clean undock reset to `presenter: null`.

### Item 2: Whiteboard Single-Tap Dot
- **Diagnosed Root Cause:**
  A 1-point stroke was dropped by three guards checking `points.length > 1` (`endDraw()`, `addWhiteboardStroke()`, `redrawWhiteboardCanvas()`).
- **Confirmation:** Confirmed. Any single click or tap produced a 1-point stroke that was discarded without rendering or sending.
- **Fix Applied:**
  - Updated guards to `points.length >= 1` in `endDraw()`, `addWhiteboardStroke()`, and `redrawWhiteboardCanvas()` in `web/game.js`.
  - Added `drawWhiteboardStroke(ctx, stroke)` helper rendering a filled circle of radius `Math.max(2.5, width / 2)` at `points[0]` when `points.length === 1`.
  - Updated in-world miniature whiteboard rendering in `web/render.js` to draw single-point dots matching the full-size canvas.
- **Verification:**
  - Automated WS test (`test/round6-interaction-tests.js` Test 7) passed: 1-point stroke successfully serialized, broadcast to remote peers, and rendered.

### Item 3: Typing-Board Input-Focus Guard
- **Diagnosed Root Cause:**
  Global `window` `keydown` listener in `web/game.js` lacked an input-focus check. Typing `e` fired the game interaction handler, closing or toggling modals while typing.
- **Confirmation:** Confirmed. Typing in `#typingBoardInput`, `#presenterTopicInput`, or drink preset inputs triggered global game hotkeys (`e`, `m`, `v`, etc.).
- **Fix Applied:**
  - Added target check at the top of `keydown` and `keyup` in `setupInput()` in `web/game.js`:
    ```javascript
    const isTyping = target && (target.tagName === 'INPUT' || target.tagName === 'TEXTAREA' || target.isContentEditable || (target.closest && target.closest('input, textarea')));
    if (isTyping && e.key !== 'Escape') {
      return;
    }
    ```
  - Allows `Escape` to blur the input and close modals smoothly.
- **Verification:**
  - Automated test (`test/round6-interaction-tests.js` Test 9) verified code guards and behavior.

### Item 4: Coffee/Carryable Consume Fix with Unified Held-Item State
- **Diagnosed Root Cause:**
  Field mismatch between `this.player.heldDrink` and `this.player.heldItem`; sip completion cleared `heldDrink` while `heldItem` or remote sync lagged.
- **Confirmation:** Confirmed. Different systems (vending, coffee-maker, fridge, HUD, rendering, remote sync) set either `heldDrink` or `heldItem` inconsistently.
- **Fix Applied:**
  - Created `setHeldItem(item)` helper on `Game` class in `web/game.js`:
    ```javascript
    setHeldItem(item) {
      this.player.heldItem = item;
      this.player.heldDrink = item;
      this.updateCarrySlotUI();
      if (this.net) this.net.sendMove(this.player.x, this.player.y, this.player.facing, this.player.isSitting, true);
    }
    ```
  - Standardized all pickup sources (vending machine, fridge, coffee station, custom drink maker) to call `setHeldItem(item)`.
  - On sip timer expiration, `setHeldItem(null)` clears the item, ends sipping, and syncs immediately.
  - Updated `server.js` and `web/net.js` to relay and receive both `heldItem` and `heldDrink`.
- **Verification:**
  - Automated tests (`test/round6-interaction-tests.js` Tests 6 & 10) verified pickup, sip animation duration, complete clearance of both fields, and multiplayer sync.

### Item 6: Background Music Rewritten to Sectioned File Playback
- **Diagnosed Root Cause:**
  Previous background music was a procedural synthesizer loop. The user requested playing sliced 3-5 minute audio files from `web/music/*.mp3` with random selection and smooth crossfades.
- **Confirmation:** Confirmed. Replaced procedural engine with native Web Audio `AudioBuffer` file player.
- **Fix Applied:**
  - Added `/api/office/music` endpoint in `server.js` to discover all `*.mp3` files under `web/music/`.
  - Added `audio/mpeg` MIME type mapping in `server.js` for clean streaming.
  - Rewrote `web/sfx.js` to load sections via `fetch()` -> `arrayBuffer()` -> `decodeAudioData()`.
  - Implemented non-repeating random section selection and 2s linear gain crossfades (`playRandomSection()`).
  - Preserved procedural synthesizer as a graceful fallback if audio file fetching fails.
  - Preserved `M` hotkey, settings toggle, and `musicBusGain` control.
- **Verification:**
  - Automated test (`test/round6-interaction-tests.js` Test 12) verified `/api/office/music` API response, file existence, and `audio/mpeg` HTTP streaming.
