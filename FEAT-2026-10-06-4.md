## Item 1 — Sound pass + sound study (subagent deep-dive)
Current state: `web/sfx.js` is fully procedural WebAudio. The key-typing SFX is annoying and harsh.

Do a SOUND STUDY first (dedicated subagent). It must produce a concrete, buildable recipe covering every
event in the office — target timbre, filter, envelope (attack/decay), pan, and relative level per event:
walk/footstep, key/typing, paper, door, chat blip, notification, clock tick, interaction/confirm, music bed.

Then rework `web/sfx.js` so the sounds are pleasing and easy on the ears:
- Key/typing specifically: make it SOFTER, lower, damped, low-passed, short, and low-gain. Remove harsh
  clicks/tones. Think muted, warm mechanical clack — not a harsh electric tick.
- Every other event: apply the same "warm, damped, low-gain, short" principle. No harsh transients.
- Add a small gain/lowpass master bus so the whole SFX bed sits comfortably under voice/music.

Add OPTIONAL BACKGROUND MUSIC — a calming office/jazz loop, cozy "jazz-café-video" vibe:
- Procedural (WebAudio), NOT a sampled file. Suggested generative approach: a slow, mellow chord
  progression (warm pad / soft triangle+sine with slow attack), a sparse, mellow "piano"/plucked melody
  line on top, and a very low noise floor (soft vinyl-like hiss / air). Slow tempo, low dynamic range.
- Low volume by default, ON by default. Add an `M` key HUD toggle (music on/off) and reflect it in the HUD.
- Keep it genuinely low so it never fights voice chat or SFX.
- Must start only after a user gesture (AudioContext autoplay rules) — resume on the same gesture that
  starts the game / first key.

Verification (item 1):
