## 1. Agents only carry papers when actually running

**Root cause (C6 diagnosis — verify it, note if different):** the harness agent state
machine in `web/agents.js` decides "go file paperwork in the Archives" on its own
timers/PRNG regardless of whether that harness is actually working. The client already
polls `/api/flow` every ~10s for subagent reconciliation (see the flow poller added in
FIX-2026-10-06-1) — each harness has live `running`, `active_sessions`, `subtasks`
fields derived from real PIDs.

**Change:** gate the "walk out with papers" behavior on that live data.
- Harness `running === true` → the working state machine may pathfind to the Archives
  with papers (existing behavior), file, return.
- Harness `running === false` → the agent stays inside its own office only: wanders
  between 3–5 waypoints inside its office walls, sits at its desk typing, maybe looks
  at a monitor. Never crosses the door. (Keep C6's receptionist behavior as-is.)
- When the running flag flips, transition smoothly (agent walks back to office if it
  happens to be out mid-cycle).
- The "working" status text on the agent's name tag should also follow the real data
  ("working · N sessions" vs "idle").
- Subagent reconciliation from `/api/flow` (fix #1 from last round) must keep working.

## 2. Cozy, decorated office — less big and empty

The 44×40 map from last round is fine size-wise. The problem is rooms feel bare.
Add procedural furniture/decoration density so every room feels like a nice place to
work. All sprites drawn in the existing canvas style (chunky vector, 32px tiles).
New decoration is non-walkable where physical (drawn as tile content or small solid
tiles) but must NOT block existing door/waypoint/desk paths — re-run the reachability
assertion after decorating.

Per-room suggestions (implement all, keep them tasteful and consistent):
- **Lobby:** rug under the reception desk, potted plants in corners, a bench by the
  wall, framed art on the north wall next to the status boards, a welcome mat at the
  door, a small floor lamp glow.
- **Each harness office:** desk chair, monitor with glowing screen (screen shows tiny
  scrolling "code" lines), desk clutter (mug, sticky notes, paper stack), shelf with
  books, a plant, a wall poster, a floor rug, desk lamp glow.
- **Break room:** fully decorated kitchen — counter with a coffee machine that emits
  a steam wisp particle, kettle, fridge, a table with 4 chairs, a plant, a snack
  shelf.
- **Archives:** shelves stay, add a rolling ladder, a "FINDING AIDS" card table,
  boxes stacked higher as the room grows (already dynamic), a small archive lamp.
- **Global:** string lights along the top wall of each room (tiny warm dots, gentle
  sway, respect the day/night lighting), subtle wood-grain variation on floor tiles
  (2-3 procedural floor variants per room), door mats at every door.

Implementation notes:
- Add a `decor` layer in `map.js` (list of {x,y,kind,variant}) built deterministically
  (seeded) so all clients render identically without extra network state.
- Collision: keep the solid grid as-is for pathfinding; draw decor into it only where
  it truly should block (furniture), and mark those tiles solid in the same grid so
  A* respects them — then re-validate reachability (doors, desks, C6, spawns,
  Archives shelves all still A*-reachable).
- Keep it cheap: pre-render static decor into offscreen canvases per room if needed;
  the frame budget is 60fps with multiplayer lerp.

## 3. Profiles: pick Nathan or Gavin (saved choice) + clock-in/out stats

Replace the free-text name field with **profile cards**: "Nathan" and "Gavin"
(two big cards with avatar preview + a distinctive default cosmetic set each:
Nathan = teal crewmate + cap, Gavin = orange crewmate + beanie, both customizable via
the existing wardrobe). The picked profile is **saved server-side**
(`data/profiles.json` upsert: {profile, color, hat, visor, face, trail, lastSeen})
and in **localStorage** (`forge_office_profile`), so both you and your friend rejoin
as the same identity automatically. Friends of other humans on the LAN who aren't
Nathan/Gavin can still use a "Guest" card with the name field (keep the old input for
that case, labeled Guest).

**Clock in/out + stats (server-side, new files + endpoints):**
- `data/clock.json` — per profile: `clocked_in_since`, `total_ms` (accumulated),
  `sessions` (count of clock-ins), `longest_ms`, `sessions_with` (number of sessions
  where another profile was also in).
- Server: presence is derived from WS connections (join = clock in if not already in,
  leave/12s-drop = clock out, record `total_ms += now - since`, increment `sessions`).
  Persist on every transition (atomic write, tmp+rename).
- New endpoints (proxied same as the other `/api/*` passthrough — these live in
  `server.js` itself, not the console):
  - `GET /api/office/presence` → `{online:[{profile,since}], stats:{per profile:
    {total_h, sessions, longest_h, sessions_with}}}` (human-readable hours).
  - No auth (LAN-only, matches the rest of the server).
- **Client stats panel:** a small "CLOCK" panel (press `K` or a HUD button) listing
  Nathan/Gavin: online dot + "clocked in 1h 12m", total hours, sessions, longest
  session, sessions together. Poll `/api/office/presence` every 10s.
- Gating: only profiles actually present via WS count as clocked in. A profile that
  never joined shows dashes.

## 4. Discord presence — "message in last 5 min = working"

Server-side (new `web/../discord-presence.js` in the project root or a `lib/` dir,
loaded by `server.js`):
- Poll the Discord REST API as the bot (read `DISCORD_BOT_TOKEN` from
  `~/.hermes/.env` at server start — the env line is
  `DISCORD_BOT_TOKEN="..."`; parse it the same way other tools do, never log it):
  `GET /users/@me/channels` won't work (bots get empty) — use
  `GET /guilds/1555057219622408275/channels` once at startup to list channels and
  pick the TEXT channels (type 0) named `c6-home`, `c6-nathan`, `c6-gavin` plus
  `general` if it exists as text; cache the resolved channel IDs. (Verified: that
  endpoint returns the c6-* channels fine with the bot token. Note: a bot's
  `GET /users/@me/channels` returns `[]` — don't use it.) Then every 60s fetch
  `GET /channels/{id}/messages?limit=50` for those channels.
- From each message: if `author.id` is one of Nathan `848334458453229659` /
  Gavin `743939830798352436`, record `lastMessageAt = max(parse(timestamp))` for
  that profile. (Webhook-free, read-only, ~10 requests/min — well under rate limits.
  Handle 429 with retry_after sleep ≤4 retries. Every request needs
  `Authorization: Bot <token>` AND a `User-Agent` header — Discord 403s without UA.)
- **Online rule:** profile is "Discord-active" if `lastMessageAt` within the last 5
  minutes. Combined presence for the UI:
  `in_office` (WS clock) and `discord_active` (message recency) — show both.
- Expose via `GET /api/office/presence` (merge into the same response from feature 3:
  add `discord:{nathan:{active,last_message_at}, gavin:{...}}`).
- **Client:** the main status board gets two little presence chips under each of
  Nathan/Gavin rows (or a dedicated "PEOPLE" section): green dot = in office now,
  amber dot = active on Discord (last message Xm ago). Also a HUD chip near the CLOCK
  panel showing your own state.
- Resilience: if the bot token is missing or Discord API fails, the feature degrades
  silently (chips hidden) — never crash the server over it. Log a one-line warning to
  the systemd journal.
