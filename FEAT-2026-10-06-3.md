## 1. Projects fully dynamic (folders + deployments DB)

**Root cause (verify, note if different):** `web/map.js` `populateProjects()`
diffs by count and only ADDS boxes when `projects.length` grows — it never removes
or updates. So a project removed from `data/projects.json` (or its folder) leaves
a stale box forever, and `deployed`/`updated` changes don't change the box.

**Change:** full reconciliation every 30s poll of `/api/projects`:
- Key boxes by project `id`. New id → box appears (existing growth logic).
- Removed id → its box fades out over ~1s and is removed from the grid (no room
  shrink — Archives stays grown, but the spot gets a subtle empty-shelf mark so the
  space reads as "was something here").
- Same id, changed fields → box label updates in place: name, `deployed` badge
  (green DEPLOYED dot vs gray dot), `updated` date small text, `description` as a
  tooltip-ish label on interact.
- Boxes sorted by `updated` desc along the shelf (newest projects at the front,
  nearest the door) so the "newest work" is most visible. Re-run the A*
  reachability assertion after any box layout change.
- Interact (E) on a box → small info card: name, description, deployed badge +
  link (open in new tab if `deployment_url`), updated date.

## 2. Plants covering the insights board + boards off-center

**Root cause (verify):** the cozy-decor pass placed potted plants on north-wall
tiles that are also `T_BOARD` (the status board strip), and the board strip
itself is not symmetric on the wall it sits on.

**Change:**
- Board strip(s) centered on their wall span: compute wall run, place the board
  tiles centered with equal gaps each side (recompute any light/waypoint/decor
  offsets accordingly).
- Decor placement rule (global, enforced): a decor item may only be placed on a
  floor tile that is not `T_BOARD`/`T_SHELF`/door/desk and is walkable-adjacent —
  i.e. decor never overlaps the board. Add an assertion in map build: zero decor
  tiles intersect board tiles; fail the build (throw) if violated so it can't
  regress.
- Visually: plants flank the board (one each side of the centered strip) instead
  of sitting on it.

## 5. Lighting study — kill real-time sync, two modes, cozy warm

**Root cause (verify):** the FIX-2026-10-06-1 lighting uses a time-of-day ambient
curve + per-player light cutout. Nathan's direction: no real-time sync at all.

**Spec (do an actual lighting study — tune values on a rendered screenshot, not
guesses; use the `--once` style dry run where possible):**
- Remove time-of-day ambient entirely. Two modes, toggle on `N` + start screen
  (persisted):
  - **Fullbright** (existing behavior).
  - **Office lights (NEW, default):** each room has 2–4 warm point lights
    (ceiling-style: lobby above desk + center, each office above desk + corner,
    break room above counter + table, archives one per shelf-bay, plus a soft
    entry light by each door).
  - Brightness = `max(ambient_floor, Σ per-light falloff)`:
    - `ambient_floor` = 0.62 (never dark — rooms stay clearly visible everywhere).
    - each light: `intensity 1.0` at center, smooth falloff to the floor value by
      ~3.5 tiles radius (cosine or quadratic — pick what looks cozy, not clinical).
    - tint lights warm (warm white ~ #ffe8c0, slight hue variation per room is
      fine — break room warmer/cooler contrast is OK if tasteful).
  - NO player light cutout (remove the personal light radius entirely).
  - Bake the resulting light grid per mode at map build (two precomputed canvases:
    fullbright=identity, office=lightmap). Toggle just swaps the overlay — zero
    per-frame cost change.
  - Coziness pass: lights pool a bit under desk lamps (small extra warm pool on
    each desk), the break room gets the strongest warm glow, Archives gets a
    slightly dimmer-but-still-bright amber mood (still ≥ floor brightness).
- HUD: `N` label shows "LIGHTS: office" / "LIGHTS: fullbright".
- Ship the study: in the report, paste the ambient_floor/falloff values used and
  the per-room light positions, plus one screenshot (day mode, office mode) so the
  study is on record.

## 8. Proximity voice chat (players only)

Users talk to each other; agents do not listen or speak. "3D-ish" = distance
attenuation + wall occlusion, no full positional panning needed (a slight
L/R skew by relative x-position is a nice-to-have, not required).

**Capture (client, sender):**
- Start screen / `V` key: "Enable mic" (getUserMedia, audio only, echo
  cancellation + noise suppression on). On start, create an `AudioWorklet`
  (fallback: ScriptProcessor) that slices 48kHz PCM16 mono into 960-sample
  chunks (~20 ms @ 48k).
- Gate: only transmit when `>0.06` RMS over 3 consecutive chunks (AGC-ish:
  normalize chunks to ~0.8 peak). ~24 kb/s per talker (960 samples × 2 bytes).
- Send `{t:'va', d: b64chunk, l: level}` over the existing WS, throttled to one
  chunk per ~20 ms max.

**Server (relay only, no storage):**
- On `va` from a client: forward to every OTHER client whose player is within
  800px of the sender (grid check). Add the sender's id to each client's
  "voice sources" set on first chunk; drop after 1.5s silence. No echo back to
  sender.
- Heartbeat-drop cleanup as existing.

**Playback (client, receiver):**
- Maintain a ring buffer per source (~150 ms), play at 48kHz through
  `AudioContext` (the existing one — resume on first user gesture like the game
  already does).
- **Distance gain:** `gain = clamp(1 - d/800, 0, 1)` then apply a lowpass
  filter that opens with distance: `freq = lerp(6000, 900, d/800)` Hz
  (far voices sound muffled/soft).
- **Wall occlusion:** every 100 ms per active source: DDA raycast on the tile
  grid from self to source. 0 wall hits → full gain. 1 → ×0.45. 2+ → ×0.15
  (doorways count as hits only on the closed-door side — doors are always
  "open" for audio in this game, so a ray passing through a doorway tile = 1
  hit, not 2, i.e. doorways attenuate less than solid walls: treat doorway
  tiles as half-hits). Smooth the resulting gain with 200 ms attack / 400 ms
  release so gain doesn't flicker as you turn a corner.
- HUD: a small mic pill (muted when not transmitting), and a "voices" indicator
  when receiving someone (their name + tiny level meter). `M` mutes BOTH voice
  and SFX as today; add `V` = voice-only mute (mic off, keep receiving).

**Verification for voice (no real mics in CI):**
- `test/voice-test.js`: two fake clients with scripted fake `va` packets: assert
  (a) a sender 200px away delivers chunks to the other within 100 ms, (b) a
  sender beyond 800px gets nothing, (c) after a wall is inserted between them
  (test map toggle) the client-side occlusion function returns the 0.45/0.15
  paths (unit-test the DDA + gain math directly — deterministic).
- In-browser: with mic denied, the "Enable mic" flow must fail gracefully (toast
  "mic unavailable — you can still hear others"), zero errors.
